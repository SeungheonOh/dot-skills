# Turn an audio CD into an identified local track set

Deliver the requested locally stored tracks, a small disc-track-to-file map and an honest account of import and playback checks. Preserve the physical disc and any existing library copies. A CD playing successfully, a library entry or a completed progress icon does not establish that the requested audio is saved locally and usable without the disc.

This workflow reads an ordinary audio CD through an available compatible optical drive and an existing supported music application. [Analog digitization](../digitize-analog-audio/SKILL.md) records an electrical playback signal; [media export](../media-export-compatibility/SKILL.md) converts existing files; [data-disc burning](../burn-data-disc/SKILL.md) writes files to a blank medium. None establishes the physical-disc track selection, import settings, metadata provenance and local-library identity covered here.

Exclude protected-content circumvention, DVD/Blu-ray extraction, mixed-mode/data-session preservation, hidden-pregap recovery, damaged-disc restoration, forensic/bit-perfect certification and full disc-image archival preservation. If those requirements emerge, retain the ordinary tracks already identified and explain the different task. Do not replace direct digital import with microphone or system-audio recording as a hidden workaround.

## Establish the source and deliverable

Use the request and available evidence to resolve:

- The actual computer, OS, music app/version and selected optical drive
- One identified physical disc, with its disc number where a set is involved, and who can load/eject it safely
- All tracks or an exact selection by physical track number, with known titles as supporting evidence
- Authority to copy the selected material and its intended private/local use; do not assume permission to distribute it
- Desired encoding/quality, need for separate tracks or an explicitly requested joined item, and required target player
- Approved local library or output destination, existing imports to preserve and available working storage
- Whether metadata lookup, artwork retrieval, library synchronization or another external service is permitted
- Required checks: membership, complete file readability, audible review coverage and any continuous-track transition requirement

Do not turn an ordinary disc into a mandatory metadata project. Unknown titles can remain neutral track labels if the user mainly wants usable files. If the intended selection is unclear, ask the one question that changes the import rather than importing everything by default.

For private recordings, use a neutral source label and avoid exposing titles, participant names or activity descriptions in public filenames, lookup requests or screenshots. Copying to a local library is not approval to submit metadata to a database, upload audio, synchronize it to an account or send it to another person. Do not make legal conclusions about a particular disc; if copying authority or a protection boundary is unresolved, hold the affected operation.

## 1. Preflight insertion, then confirm the audio-disc source

Before asking anyone to load the disc, inspect the app's insertion action, automatic online metadata lookup and relevant library synchronization behavior. Insertion itself can trigger import or a lookup; [Apple's CD-information guidance](https://support.apple.com/en-gb/guide/music/mus2561f46f8/mac) describes automatic retrieval when connected. Do not wait for the track list to appear before enforcing a local-only or no-lookup request. Also establish the intended local destination and a safe collision policy before any automatic import could begin.

Use a supported show/ask behavior rather than automatic import when selection and settings still need review, changing only preferences within the user's authority. For a no-lookup/private-disc request, establish a supported route that does not send disc information externally before insertion. If this cannot be established without an unapproved privacy, account or network change, hold before loading and explain the missing decision. Do not disconnect the whole computer or alter account-wide sync as an incidental workaround. Record any approved temporary setting for later restoration.

If the disc is already inserted, inspect whether an import or lookup has already started. Stop further preventable activity through an authorized supported control, preserve any partial state and disclose the known scope; do not promise that an external request can be recalled or that the preflight happened in time.

After that gate is satisfied, have the local operator identify and insert the intended disc using the drive's supported handling. If several drives are present, bind the displayed track list to the correct device. A matching album title alone is insufficient when several editions, discs or previously imported copies share it.

Inspect the app's optical-disc view, not a cloud album or existing library result. Record the physical track numbers, displayed durations and requested selection before import. Compare with the disc label or user-supplied track listing when available. Metadata can be missing or wrong; keep the numbered source list independent of names.

Distinguish an audio CD from a data disc containing ordinary audio files. For a data disc, preserve and copy the approved files through an appropriate file-transfer workflow instead of pretending they need audio-CD ripping. Do not launch an included executable, bundled player or installer just to access audio. An unknown autorun or security warning is a stop, not part of ordinary import.

If the drive cannot recognize the disc, establish the supported media/drive combination and exact error. Do not repeatedly spin a visibly damaged, cracked or unstable disc, attempt mechanical repair, change region/firmware settings or force ejection. A user or capable operator must handle physical conditions; remote app control does not supply that capability.

No optical drive or no supported installed reader means a preparation result. Purchasing a drive, installing an app/driver or changing device permissions is separate from the requested import unless already authorized. Do not substitute a streamed edition with similar titles: it is not evidence of copying this physical source.

## 2. Protect the existing library and local destination

Inspect only the relevant library location and selected album/track identities. Establish whether an earlier import exists and whether it is local, linked to another location or supplied by a streaming service. Same title, artist and duration do not prove two entries represent the same source or bytes.

Record how this attempt will remain distinguishable: source/disc number, selected tracks, actual settings and import time or an approved attempt label. Prefer a supported fresh local destination or separate library when needed to preserve existing copies, but do not switch, relocate or rebuild the user's entire library merely to avoid a collision. Confirm the route first; if the app cannot safely isolate a retry, stop for the required replacement decision.

Inspect any overwrite, replace or duplicate-import prompt. A request to import does not authorize deleting an earlier rip, ratings, playlists or cloud-library entries. Keep old copies until the new set is verified and any cleanup is explicitly approved. A library Delete control can have a different effect from removing a local file; inspect its scope before later cleanup. Permanent deletion requires its own exact-target action-time confirmation.

Check the actual media folder, available space and whether that folder is synchronized or shared. Do not rely on its friendly “Music” label as proof of local-only storage. Inspect existing library synchronization behavior before adding private tracks; if import would share them outside the approved scope, hold or choose an already supported authorized local-only route. Do not disable account-wide sync or change security/network settings without the required authority.

Capture the task-relevant current preferences before changing them. Import format, metadata retrieval, automatic import/eject and library organization can affect later discs too. Make only the requested or necessary authorized changes, record which are temporary, and restore those afterward when appropriate without overwriting an intervening user change.

## 3. Choose settings before the read begins

Read the installed app's current official import documentation. Decide the actual encoding before starting, rather than accepting a default and renaming the result later. Resolve the trade-off once:

| Requested outcome | Setting decision | Limit to retain |
| --- | --- | --- |
| Preserve the acquired audio without lossy compression | Choose a supported lossless/uncompressed format and source-appropriate settings | This does not prove the drive read every sample correctly |
| Smaller listening copies | Choose the user-approved supported lossy format and quality | Do not describe the result as lossless or an archival master |
| A specific player must use the files | Check that player's documented format support | Local import success does not prove target-player acceptance |
| Continuous music spans adjacent tracks | Preserve source order and verify the transition in the intended player | Player crossfade/gap behavior can differ from stored boundaries |
| Required special disc structure or exact image preservation | Stop this track-import path | Ordinary song files do not represent every disc structure |

Do not upsample, downmix, normalize, trim silence, change speed or join tracks as cleanup. A higher output rate or larger file cannot recreate missing source detail. Preserve separate numbered tracks by default; joining changes the output structure and needs a clear request. Any requested processing should produce a separately identified derivative after the untouched import is secured.

### Music on macOS

[Apple's CD-import guide](https://support.apple.com/guide/music/import-songs-from-cds-mus2935/mac) describes selecting the disc in Music, choosing tracks and using Import CD. Inspect the insertion behavior first so an automatic full import cannot precede selection and settings. If an immediate import prompt appears before preparation, decline that import and inspect the disc instead.

[Apple's import-settings reference](https://support.apple.com/en-ng/guide/music/muscd653d63/mac) places the controls under Music > Settings > Files > Import Settings. Choose the actual available encoder/settings and decide whether to use its audio-CD error-correction option. Record the final values. Error correction is not a certificate of perfect extraction and can affect read time; do not silently turn it off to make a problematic disc finish faster.

[Apple's Files settings](https://support.apple.com/en-ie/guide/music/mus0f5accea/mac) distinguishes the media-folder location from organization and copying preferences. Inspect the real destination without invoking whole-library consolidation or moving old media. Use the version selector and observed interface where labels differ.

### Windows Media Player

[Microsoft's CD ripping guide](https://support.microsoft.com/en-us/windows/apps/windowsmediaplayer/burn-and-rip-cds) describes choosing tracks, Rip settings and Rip CD, with a configurable output location. Match the instructions to the actual installed Windows Media Player edition; do not assume another app merely named Media Player has identical controls. If the documented route is unavailable, report the capability gap rather than installing an alternative automatically.

Inspect the format/quality and destination before Rip CD. The guide notes that changed rip settings apply to future imports, not files already ripped. Re-importing from the source is a separate attempt; changing a menu afterward does not upgrade the existing file. Avoid the Burn tab, synchronization controls and unrelated library actions.

## 4. Reconcile names without changing the source identity

A readable audio disc may display generic track names. Keep track numbers and disc identity as the stable map while selecting metadata. If lookup is allowed, compare the returned album/edition, track count and order against the physical source. A plausible first result can belong to a different release. Do not accept artwork or a cover title as proof of audio identity.

[Apple's song/CD-information guide](https://support.apple.com/en-gb/guide/music/mus2561f46f8/mac) describes retrieved CD information accompanying imports. Treat it as a metadata proposal. Correct only supported fields for the selected batch, using the user's supplied list or verified source. Do not fill missing composer, performer, date or edition facts from guesswork.

For a private or unidentified disc, neutral labels such as `Disc-01 Track-03` are preferable to uploading a track or submitting private titles to find a match. Never submit metadata back to an external database without separate approval. Artwork downloads, online matching and library sync are distinct from local import; keep their actual recipients and effects visible when permission is needed.

Record track and disc numbers in the app's appropriate fields when supported, not only in display titles. If the app organizes paths from tags, make metadata changes through its supported interface and recheck actual file locations afterward. Do not manually rename its managed files behind the library's references. Resolve filename collisions without choosing one similarly named track as the winner.

## 5. Import once and account for interruptions

Recheck the physical disc, drive, selected track list, encoding, destination and duplicate policy immediately before starting. Use one import operation in one application. Do not let two readers compete for the same disc or queue a second full import after a timeout without checking the first operation's state.

Observe per-track and overall results. Record failed or incomplete tracks against the independent source list, not just the subset that appeared successfully in the library. Do not shrink the requested denominator when a track is skipped. If the app lacks detailed read-error evidence, retain that limitation instead of interpreting a completion badge as a secure-rip verification.

If interrupted, use the supported stop control and inspect what has actually been saved. Apple's import guide explicitly notes that tracks imported before cancellation remain in the library. Preserve those entries and any useful partial files until their identity and readability are known. Do not assume Stop rolls back the entire import or that a partial track is complete because it has a title.

Wait for the current read to reach a known state before ejecting or disconnecting the drive. If the control session disconnects, inspect the same operation when access returns; do not blindly press Import again. Keep the disc and drive stable, and do not change power policy or force-close another app to accelerate the task.

A retry should address an evidenced cause: selected-track mistake, a documented read setting, a safely identified alternative compatible drive already authorized, or a destination problem. Give the retry a distinct identity and preserve the previous attempt. Physical cleaning/handling must follow the disc/drive manufacturer's guidance by a capable operator; this guide does not prescribe abrasive repairs or repeated reads of deteriorating media.

## 6. Prove that the saved tracks work without the source

After import reaches a terminal state, locate the exact new library entries and their underlying local files through supported app inspection. Do not verify against the optical-disc view, an older rip or a streamed matching album.

When safe, eject the original disc through the normal control and have the operator retain it. Select the saved file/entry explicitly for verification. Disc removal proves only source independence, not network independence: establish that playback uses the inspected local path rather than a cloud substitute. Do not disable the computer's network as an unrequested test.

Reconcile the complete selected set:

1. **Membership and identity:** every requested physical track maps to one identified accepted file; missing, duplicate and unintended tracks are explicit. Preserve disc number and order even when names repeat
2. **Encoding and storage:** inspect actual codec/container, channel count, duration and local path; the configured encoder is intent until the result is inspected. A library row or file extension alone is insufficient
3. **Readable content:** use available safe playback/decoding for the complete required streams. A successful header probe establishes less than a complete decode. State any unsupported check instead of claiming it ran
4. **Audible correspondence:** listen to requested coverage through an actual audio-perception capability or attribute the result to the local operator. Include beginning/end and reported problem intervals; if complete listening is required, review every selected track. Playback commands and waveforms are not listening evidence
5. **Boundaries and order:** compare plausible source durations and content anchors without demanding identical rounded display values. For continuous tracks, inspect the affected transition in source order with the target player's relevant playback settings understood; do not hide a gap by adding crossfade
6. **Library preservation:** verify that prior selected-to-keep entries and source media remain intact to the inspected scope. Confirm no unapproved replacement, sharing or account action occurred

Clicks, truncation, repeated material or mismatched audio keep the affected track unresolved. Distinguish an audible fault on the original source from a suspected read error only when the comparison supports it. A repeated import producing matching hashes can show repeatability of those outputs, but does not itself prove agreement with every original disc sample. File hashes that differ after tag edits also do not prove the audio changed; avoid whole-file-hash claims that ignore metadata.

If target-player compatibility was required, exercise the actual local files there through the authorized path. If the player is unavailable, report local import/playback evidence and leave target acceptance pending. Do not upload tracks to a conversion or validation service to obtain a stronger check without permission.

## Recovery, acceptance and handoff

Retry only the affected tracks when the app supports an isolated safe attempt and the cause has changed. Do not delete a usable earlier copy before its replacement is checked. If repeated read failures, unsafe physical media, protected content or unsupported structure remains, stop and deliver the verified subset explicitly as partial, with the unresolved source tracks listed.

Restore task-temporary import or insertion preferences when appropriate and read them back. Keep the chosen retained settings explicit, since they affect future imports. Leave the disc safely ejected if that was the agreed ending. Cleanup, a backup job, device sync, public sharing and disc disposal remain separate actions.

Return a concise receipt: disc/source label, selected physical tracks, accepted filenames/local library identity, actual encoding, metadata provenance, import errors/retries, playback coverage and remaining gaps. Include the source-to-file map when names or duplicate attempts make it useful; do not expose unrelated library contents.

Call the task complete only when the requested track set is represented, required local checks pass, preservation requirements hold and any requested target check is satisfied. Use **prepared**, **imported; verification pending**, **verified to the stated scope** or **partial/blocked** honestly. Do not claim bit-perfect extraction, archival completeness, source ownership verification or a listening result unsupported by evidence.

## Fictional, unexecuted illustration

A fictional user has an ordinary six-track audio CD of their own instrumental recordings. They request tracks 2 through 5 as separate local lossless files, with no online lookup or library sync. An earlier lower-quality copy of track 3 must remain untouched.

The proposed workflow would establish an authorized no-lookup, local-only insertion route before loading the disc, or hold if that route were unavailable. It would then identify the physical disc, record four selected track numbers and use neutral labels because no public metadata is needed. It would inspect the local destination and existing track-3 entry before choosing a supported non-overwriting import route. If the app could not isolate the new attempt from the old copy, the operation would stop for that decision.

Suppose the paper scenario says tracks 2, 3 and 5 import, while track 4 reports a read error. That would remain a three-of-four partial result, even if all visible new library rows play. A documented error-correction retry could target track 4 only after preserving the first attempt and confirming its destination. No old track would be deleted just to hide a duplicate.

Expected acceptance would map all four requested physical tracks to the accepted files, inspect their actual encoding, eject the source and play the exact local outputs with the agreed audible coverage. If the retry remained faulty, track 4 would stay unresolved and the receipt would identify the usable subset.

This is an original fictional decision walkthrough. No disc, drive, app, account, file, import, lookup, playback, listening check or retry was operated or executed for it.
